# 本地评测方案

2026-10-25。开发数据与正式 AML 套件分开；本地分数不外推为官方成绩。

## 数据

主开发：Mem-Gallery 的跨会话图文对话；第二来源：ATM-Bench 的跨来源与时间验证。两套分阶段使用，不同时跑两套全量消融。官方 Smoke 是接口兼容检查，不能代替本地质量验证；目前未找到独立可下载的 AML 第二期多模态开发包。[来源](https://agentmemoryleaderboard.ai/competition/)

Mem-Gallery 发布仓库：Ethan-Bei/Mem-Gallery，元数据声明 MIT、公开免申请。下载固定 revision，manifest 保存文件路径/字节/哈希。使用完整话题历史，不按 gold 缩小库。初期确定性小样本只证明管线与初步基线，不代表整套数据。

划分规则预先固定：话题名 SHA256 整数模5等于0为holdout，其余dev；按字典序分别选第一个话题作为初轮管线样本，保留完整会话及全部记忆和问题。当前是话题级小样本，不能声称验证全部话题的泛化。开发人员只看留出聚合指标；如分析留出题并据此调参，则将其归开发并另选未查看的话题。

2026-10-25兼容性调整：首个holdout（Architecture_Art_Culture_Exhibition_Technology）实际有两张JPEG分别11,241,671/11,126,998字节，超过10 MiB，管线明确失败且没有报告该话题质量分数。保留原图、不缩放、不按clue或题目跳过；读取同revision的blobs元数据后，选按原顺序下一个所有图片均不超过10 MiB的holdout，即Astronomy_Physics_Scientific_Experiments_Cosmology。原失败话题仍保留并单列为媒体兼容性案例；这一选择基于接口上限，不代表正式Adapter的缩放策略。所有被选话题仍下载完整记忆及QA图片。

## 本地适配约定

- JSON `multi_session_dialogues` 独立转换，QA/gold 不进入写入函数。
- 每轮分为原始 user 与 assistant 消息；input_image、原始 image_caption 按顺序随 user 写入，保留所有图片，不照搬上游只取首图的捷径。
- 日期按 UTC 零点转换为 timestamp，角色文本不合并；该来源只有日期精度。
- 每轮 source round ID 映射到两个角色消息的 evidence_id；clue 命中按轮次统计，任一角色消息可命中该轮，故轮命中不等于语义证据已经完整。图片 ID 只映射实际带图的消息。
- `question_image` 使用实际原图，不添加其 gold；当前B0不理解图像，相关问题仍完整计入结果。
- 不调用来源数据中已有的QA答案、隐藏引用或clue进行索引增强；不导入其他模型预处理结果当作本项目抽取。
- 文件后缀有时不符合图片真实格式，本地序列化按实际格式声明MIME，保留原始字节；HTTP侧仍严格验证声明与内容一致。
- 未映射clue、缺图、错MIME或路径越界明确报错，不默默跳过难题。

此适配是透明的本地研究口径，不宣称等同 AML 冻结 Adapter。原始数据含名字等人物资料，B0仅写入对话/已有caption及日期，不把character_profile背景全量注入。

## 消融与指标

| 配置 | 主要变化 |
|---|---|
| B0 | 原文/caption + scope内BM25，命中回传原图 |
| B1 | 指定LLM增加结构化视觉/OCR注释 |
| B2 | 指定文本向量 + 多路RRF |
| B3 | 有来源实体/事件/时序关联 |
| B4 | 查询条件原图核验及只回文本/回图对照 |
| B5 | 证据覆盖与字节/token预算选择 |

报告 Recall@1/5/10/20/100、全部gold clue命中率、MRR、Add/Search耗时、媒体字节与调用费用。多个索引视图不重复计数；最终选择并回传后的证据用于指标。无clue问题保留并计数，不把空gold算作召回成功；它们需后续Answer/Eval验证拒答与冲突处理。

每次实验用新的输出目录和数据库；拒绝复用旧目录，manifest对文件逐项校验。逐题结果留在被忽略的runs目录，公开文档只整理有来源且可发布的聚合结果。

后续按能力分项及独立留出置信区间评估增强，最终回答使用固定本地代理配置并明确与官方区别。当前检索测试不调用回答/评分模型，不能报告QA准确率。
